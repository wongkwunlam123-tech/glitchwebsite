用  @keyframes  控制颜色与透明度的平滑循环
呼吸感的核心不是单纯变大变小，而是模拟自然起伏的节奏感：起始稳态 → 缓慢扩张 → 短暂停顿 → 柔和回缩。CSS 中最直接的方式是同时控制  opacity  和  transform: scale() ，再叠加色相（ hsl() ）变化实现颜色循环。
关键点在于时间函数和关键帧分布：不能用线性，得用  cubic-bezier(0.4, 0, 0.2, 1) （即  ease-in-out  的变体），且 0% 和 100% 帧必须完全一致，中间 50% 设为峰值状态。
颜色用  hsl()  而非  rgb()  或十六进制，方便通过  h  值做循环（比如从 0 到 360） 避免在  0%  和  100%  写不同值，否则动画会跳变 若用  background-color  动画，确保元素有明确尺寸（ width / height  或  min-width ），否则缩放不可见
避免  animation-timing-function  错配导致“卡顿感”
很多人用  ease  或默认  ease ，结果呼吸节奏生硬、像抽搐。真正呼吸是“吸气慢→屏息→呼气略快”，对应动画曲线应是非对称的：前半段缓入更长（0%→50% 占 60% 时间），后半段稍快回弹（50%→100% 占 40%）。

@keyframes breathe {

注意： hsl(360, ...)  等价于  hsl(0, ...) ，保证首尾颜色无缝衔接； scale(1.08)  是经验上限，超过 1.1 就容易失真。
用  animation-iteration-count: infinite  时别漏掉  animation-fill-mode
如果不设  animation-fill-mode: forwards ，动画第一帧开始前元素会处于未定义状态（比如透明或无背景），造成闪一下才启动。而  forwards  能让元素停留在最后一帧样式——但这里恰恰不能用它，因为循环动画需要回到起点。

在 React/Vue 等框架中动态控制呼吸节奏的坑
如果想用 JS 控制呼吸频率（比如根据用户心跳数据调整周期），不要直接改  style.animationDuration  —— 这会重置整个动画，导致“重吸一口气”的突兀感。
